# M16 — Minimal Durable Session / Interaction Continuity (pre-implementation contract)

> Status: contract only; implementation and validation have not started.
> Baseline: `main` at `301ab567da29f9654799625f0de159596f0c962a` (M15 complete and pushed).
> Architecture: [Session](../02-Architecture/Runtime/Session.md), [Task](../02-Architecture/Core/Task.md), [Context](../02-Architecture/Runtime/Context.md), [Runtime State](../02-Architecture/Runtime/State.md), and Accepted DDR-001–006.

## Goal, timing, and existing behavior

M1–M15 authenticate independent HTTP requests and, where appropriate, persist capability-owned Task/Execution records and M12 operational routing audits. They have no durable Session/Interaction boundary. M16 proves that one authenticated user can explicitly create a bounded interactive Session, associate at least two **existing** `/requests/route` requests with it, inspect those references after a NOAH process restart, and close the Session without changing any delegate's result. This is a continuity metadata slice, not a new cognitive or execution capability.

M11 read routing, M13 explicit save routing, M15 explicit suppression routing, and their M12 audit stages remain authoritative and optional without a Session. Session does not select a route, authorize a capability, change its arguments, or become a source of model Context. `noah.users` is the authenticated API principal; it is **not** DDR-005's protected NOAH Identity Core.

## Architecture boundaries and minimal definition

For M16, a Session is a user-owned **reference and lifecycle boundary** for interactive requests. It is distinct from Task, Task State, Conversation, Message History, Turn, Context, Runtime, Execution, Agent, Agent Instance, Identity, Memory, and Permission. The Session record is authoritative only for its **own** owner and active/closed lifecycle. Existing audit and capability records remain authoritative for their own observations, Task/Execution status, Memory, and Evidence. Session association states that a routed request reached the M12 audit reservation boundary while this Session was active; it does not assert that the model, delegate, or HTTP response succeeded.

Task canonical progress stays in `noah.tasks`; Runtime owns the actual execution lifecycle. Task and Session are independently identified references, not parent/child ownership: a Task may span Sessions; a Session may refer to multiple Tasks. Closing a Session neither completes nor cancels a Task or Execution and does not alter a Task deadline. No existing execution must acquire a Session. Session owner status never grants Memory, project, or capability permission; all existing delegate authorization and disclosure rechecks still apply.

The first slice stores no Conversation or message body and does not construct or replay Context. An old Session reference is not current permission or current environmental truth. Context remains a bounded, reconstructable projection from separately authoritative sources.

## Included scope and minimal lifecycle

Only authenticated, user-owned interactive Sessions are supported. Creation makes a Session immediately `active`; M16 has no separate `created` state. The only state transition is `active → closed` on an explicit owner request. Inspection works in either state. Closing prohibits **new** routed associations but keeps earlier ones. An owner repeating close gets a read-verified `already_closed` success with the original `closed_at`; it creates no new mutation or execution record. This verified no-op is not an automatic retry mechanism. No reopen, deletion, idle, pause, expiry, archive, TTL, or failed Session status exists in M16.

The minimal durable `noah.sessions` proposal has `id` (server-generated UUID primary key), `owner_user_id` (FK to the current `noah.users` principal), `created_at` (timestamptz), and nullable `closed_at` (timestamptz). Public `status` is **derived**: null `closed_at` means `active`, otherwise `closed`. `closed_at` must not precede `created_at`. A stored `status` or `updated_at` would duplicate these two-state facts and is unnecessary. No revision, Identity Core ID, task ID, conversation ID, runtime ID, credential, body, or generic relationship metadata is stored in this table. The `owner_user_id → users` FK uses PostgreSQL's existing-project `ON DELETE NO ACTION` convention, not cascade deletion. A future principal/Session deletion policy requires separate review; M16 adds no delete path.

## Correlation design decision

| Option | Current benefit | Current cost / risk |
| --- | --- | --- |
| **A: nullable `session_id` FK/reference on `noah.routing_audit`** | One existing durable `router_id` row is the association. Session validation, row lock, and audit reservation can commit atomically; old rows remain null. Bounded lookup can use `(session_id, created_at DESC, router_id DESC)`. | Applies only to the currently routed interaction, and FK retention constrains a future Session delete. This is acceptable because M16 has neither non-routed association nor deletion. |
| B: separate Session↔router association table | Leaves audit schema untouched and could later cover other interaction types. | Adds a second row, uniqueness/ownership and atomic-write rules, another cleanup path, and a premature generalization for M16's sole `/requests/route` input. |

**Choose A.** The additive migration adds only the minimal Session table, a nullable `routing_audit.session_id` FK, and the index needed for bounded owner inspection. A null value keeps all historic and unscoped M12–M15 rows valid. The `session_id → sessions` FK also uses `ON DELETE NO ACTION`, with no cascade or M16 deletion path. Both FKs preserve reference integrity; they do not decide a future deletion policy. The audit FK does not imply Task/Execution ownership or proof of audit completion. M12's stage, result, correlation, and failure meanings remain unchanged. `router_id` remains a request audit ID, never a Session, Task, Execution, or idempotency key. No audit row is created for Session create/read/close.

Session inspection exposes only associated `router_id` and association time (the audit row's `created_at`). It is **not** a general Routing Audit browser: do not expose raw audit payload, route/failure details, delegate IDs, Task/Execution truth, or question text through this API. Future non-routed interactions require a new bounded contract rather than a polymorphic reference table now.

## HTTP API and exact request shapes

The following are **proposed M16 endpoints**, not existing routes. All require the existing Bearer credential and safe JSON responses; Session UUIDs use canonical lowercase hyphenated text. The public Session object contains `session_id`, derived `status`, `created_at`, and nullable `closed_at`; it never includes `owner_user_id` or credentials.

| Operation | Request | Confirmed result |
| --- | --- | --- |
| Create | `POST /sessions` with exactly `{}` and no query string | HTTP 201, `status=succeeded`, `outcome=created`, Session object. A fresh server UUID is returned. |
| Inspect | `GET /sessions/<session_id>` with optional `limit` and `cursor` query parameters | HTTP 200, `status=succeeded`, Session object, bounded `interactions` references, and nullable `next_cursor`. Works after close. |
| Close | `POST /sessions/<session_id>/close` with exactly `{}` and no query string | HTTP 200, `status=succeeded`, `outcome=closed` on transition or `already_closed` after verified no-op; Session object with persisted `closed_at`. |
| Associate | Existing `POST /requests/route` with optional single `Noah-Session-Id: <session_id>` header | Existing routed response, status, body, and `router_id` semantics. The header is **not** included in model input or request JSON. No header preserves the legacy route behavior. |

The dedicated header is chosen over an optional top-level JSON field: current M11/M13/M15 bodies have exact shape checks, and a header avoids changing those payloads or accidentally forwarding Session metadata to a model/delegate. A path prefix would multiply routing endpoints. Reject duplicate, empty, noncanonical, or malformed Session headers with HTTP 400 `INVALID_SESSION_ID` **after authentication and before audit/model/delegate work**. Do not silently ignore a provided invalid header. Session headers on other routes are not M16 association requests and confer no authority. The existing `Idempotency-Key` remains solely M4/M13's write key.

Session API errors use the existing safe failure-envelope style with an ephemeral request diagnostic ID and null Task/Execution IDs. Missing/revoked token is HTTP 401 `UNAUTHENTICATED`. A malformed Session path ID or create/close JSON/query shape is HTTP 400 `INVALID_REQUEST` (malformed route header specifically uses `INVALID_SESSION_ID`). A nonexistent **or foreign** Session is HTTP 404 `SESSION_NOT_FOUND`, with identical outward message and no owner or lifecycle details. An owned but closed Session supplied to `/requests/route` is HTTP 409 `SESSION_CLOSED`; no new audit/model/delegate runs. Definite database unavailability is HTTP 503 `SESSION_STORAGE_UNAVAILABLE`. None of these errors claims a new Task or Execution.

Inspection defaults to `limit=20`, permits integers 1–100, and rejects any other/duplicate query parameter or malformed cursor with HTTP 400. Order is `routing_audit.created_at DESC, router_id DESC` (stable tie break). Fetch at most `limit+1` authorized references and return an opaque, bounded cursor containing the last pair **and bound to the Session ID**. A cursor from another Session is invalid. Pagination is keyset-based, not a multi-request snapshot: later associations may appear on a fresh first page. The response contains only `{router_id, associated_at}` per interaction. Closed Sessions use the same bounded inspection. No unbounded history dump is allowed.

The new association header does not modify the response body for Session-less requests. For Session-scoped requests, the existing route response need not add a second Session field: the caller already supplied the ID, and the durable audit row is the verifiable association. No model message contains the header, Session ID, owner, lifecycle, timestamps, or linked IDs. A caller who writes such text into their own `question` remains governed by the existing question contract; M16 adds none of it.

## Authentication, authorization, association, and races

Authenticate first. Session create/read/close verify the original token against the current user principal at their DB boundary. Read and close check owner in the database. Session ID possession alone is not authorization. Session checks never replace project membership, Memory visibility, M14 target authorization, or any existing delegate/final-disclosure check. A cross-user Session ID and an unknown ID are outwardly indistinguishable.

For a scoped route, preserve existing routing preflight (including payload validation, question screening, and any project precheck). The routing model is **not** called yet. In the **same short transaction as M12 `routing_audit` reservation**: revalidate that the original token still identifies the same actor; lock the referenced Session row for update; verify actor ownership and `closed_at IS NULL`; insert the audit row with the Session FK; then commit. Only a confirmed commit makes the association durable and permits the model stage. No transaction spans a model or delegate call. No Session association is created for an unauthenticated, malformed, forbidden, or preflight-rejected request. An invalid/foreign/closed Session stops before model and delegate; non-owner and absent IDs get the same 404.

Session close locks the same row and conditionally sets `closed_at` in one short transaction after token/owner revalidation. If close commits **first**, a subsequent scoped reservation sees closed and creates no audit association. If reservation commits **first**, its association remains valid even if close commits before the model/delegate finishes. Close does not cancel, fail, or rewrite that in-flight route or its existing audit/capability records. This row-lock order is the M16 close-versus-association boundary; an earlier unlocked precheck is never authoritative. Cross-user isolation is checked again when listing references. The token check and transaction do not promise impossible linearizability against a revocation committed *after* that check; existing delegate permission rechecks remain in force.

## Transaction, failure, and unknown-outcome semantics

Session create inserts the row and commits in one transaction. Close commits only the lifecycle change; read is read-only. A definite pre-commit database failure rolls back and returns a safe deterministic error. A lost connection or commit acknowledgement that leaves the commit uncertain is **not** a confirmed failure. The M16 outward unknown envelope follows NOAH's existing safe failure style (as M14 does): HTTP 503, top-level `status="failed"` for the unconfirmed HTTP operation, top-level `outcome="unknown"` for the **database transition**, an ephemeral `request_id`, `task_id=null`, `execution_id=null`, and `failure={"code":"SESSION_OUTCOME_UNKNOWN","category":"Environment Failure","message":"Session outcome cannot be confirmed","recoverable":true,"retryable":false}`. Here `status="failed"` does **not** assert that the Session transaction rolled back or that its outcome is deterministically failed; `outcome="unknown"` is authoritative on that question. No automatic retry or fallback occurs.

On uncertain **create** only, include top-level `session_id="<server-generated UUID>"` as a provisional read-only lookup reference if the response can be delivered; do not present a confirmed Session object or state. On uncertain **close**, omit `session_id` from the envelope because the caller already supplied it in the path; inspect that path ID read-only when storage returns. If the create response is lost before the caller learns its ID, M16 cannot recover it by guessing content or creating another Session. M4 Memory Write idempotency is not reused and M16 adds no Session-create idempotency system.

For uncertain close, the caller knows the ID from the path and can inspect current state read-only when storage returns. An observed `closed` or `active` state is the state at inspection time; it is not a license for an automatic repeat close. The explicit, authorized `already_closed` path is a verified no-op with the persisted timestamp and no new durable work record. A lost HTTP response can leave the caller unsure even when the database committed.

For scoped routes, audit reservation failure/acknowledgement uncertainty preserves **M12's** `ROUTING_AUDIT_UNAVAILABLE` / `ROUTING_AUDIT_OUTCOME_UNKNOWN` boundary: do not call the model or delegate, do not create a second audit row, and do not automatically resend. A possibly committed reservation may already contain `session_id`; its presence proves only the reservation/association, not delegate execution. Later `route_validated`, `dispatch_prepared`, `observed`, delegated result, final audit failure, and `routing.audit_status=recorded|unconfirmed` retain their M12–M15 meanings. Session close or failure never converts a delegate's success, failure, or unknown result into a different outcome. **Unknown Outcome != Failed.**

## Task / Execution and privacy ownership

Session create, inspection, close, and a verified repeated close are lifecycle/metadata operations, **not user-goal Tasks or capability execution attempts**. They create no `noah.tasks`, `noah.execution_records`, Capability Evidence, or M12 routing audit rows. The Session row and its timestamps are the minimal durable lifecycle proof. A scoped `/requests/route` still creates exactly the records its existing branch owns: M3/no_action have no Task/Execution, M10 owns its pair, M13 uses M1/M4's write records, and M15 uses M14's suppression records where a real transition occurs. The Session FK introduces no parent Task or duplicate execution.

Neither Session metadata nor its inspection endpoint stores or exposes question, model prompt/raw output, Memory/document/answer body, quote, credentials, token or hash, DB password, OS path, or private data copied from the delegate. The new FK is a UUID reference only. Owner inspection returns bounded IDs and times, not a general audit API. Access control is rechecked on each inspection; a stale Session association never provides access to an underlying Memory, project, Task, or Evidence.

## Backward compatibility and explicit exclusions

Existing `/requests/route` without `Noah-Session-Id` retains its exact M11/M13/M15 JSON shapes, model messages, delegate selection and result envelope, and M12 audit stages; the new nullable column is null. Existing direct Memory and document APIs remain Session-less. The additive schema must preserve existing rows and the PostgreSQL named volume; no reset, table recreation, backfill, or reinterpretation of M12 audit/Task/Execution truth is permitted. The new schema remains after synthetic cleanup; compare the original 18 tables' row counts/private fingerprints against their baseline and confirm only test-owned Session/audit rows were removed.

M16 excludes Conversation/Message/Turn storage or replay, automatic Memory/Knowledge extraction or Context injection, general Context Manager/snapshots, long-running Task or Runtime pause/resume, automatic recovery/retry, NOAH Identity Core, personality, Agent loop, planner/DAG, autonomous or multi-agent execution, generic capability/interaction registry, event sourcing/bus, Session reopen/TTL/archive/deletion, system/background/non-interactive or project/workspace Sessions, permission inheritance, and mandatory Session adoption by existing capabilities. Future extension is not a reason to generalize this schema.

## Validation plan and acceptance criteria

**Deterministic automated tests, after implementation:** authenticated create; unauthenticated/invalid token denial; owner read; foreign and nonexistent 404 equivalence; active→closed and retained read; verified `already_closed`; malformed/duplicate header and JSON; bounded default/max/keyset pagination and cross-Session cursor rejection; two scoped routed requests under one Session; distinct-Session isolation; server/process restart readback; unscoped legacy response and null FK; closed Session denial before new audit/model/delegate; close-versus-reservation ordering in both directions; token revocation and owner checks; existing capability permission rechecks; zero duplicate Task/Execution; close leaves prior audit/Task/Execution/Evidence untouched; no Session data in model messages or forbidden content in Session rows; definite and uncertain DB/commit failure with no automatic retry. Preserve M11–M15 branch tests and run full M1–M15 regression. Use synthetic owners and exact cleanup; compare pre-existing counts/fingerprints and named-volume identity.

**Actual model:** M16 adds no selection prompt, schema, or model input. A new route-quality benchmark is not an M16 acceptance gate. If the operator uses real local Ollama in E2E, record route selection separately from Session correlation; never repeat an unexpected selection until it appears successful.

**Operator manual HTTP E2E, after implementation:** snapshot the existing private DB baseline and volume; use a synthetic user/token and no personal Memory or document. Create one Session. Send exactly two planned payload-free, Session-header-scoped routed requests using safe synthetic questions (read-only or `no_action` candidates; no Memory mutation payload). Verify their distinct existing `router_id` rows reference the one Session, without asserting semantic model quality as Session proof. Stop the NOAH process and restart the working implementation; inspect the same Session and two bounded references as owner. Close it; verify a new scoped request is rejected **before** new audit/model/delegate work and earlier audit/capability rows remain unchanged. Do not resend uncertain routed requests or inject commit failures in the live run. Stop only services started for this run, verify exact synthetic ownership/IDs, delete only synthetic rows in safe dependency order, confirm original counts/private fingerprints and named volume, and preserve unrelated Ollama and data. If an actual route differs from the planned safe outcome, stop and report; do not repeat the request.

M16 is complete only when durable restart continuity, owner/non-enumerating isolation, bounded inspection, race-safe close, legacy route compatibility, failure/unknown boundaries, automated regression, separate synthetic manual verification, and exact cleanup are demonstrated. This document records **requirements**, not validation results.

## Accepted decisions and implementation order

DDR-001 keeps Task State separate from Session and Runtime. DDR-002 keeps Agent judgment separate from infrastructure enforcement. DDR-003 keeps Memory/Knowledge distinct from Context and Session. DDR-004 keeps Artifact/Evidence ownership outside Session. DDR-005 protects the future NOAH Identity Core separately from today's `noah.users` principal. DDR-006 keeps explicit Task/Context/Result/Verification contracts without requiring a particular framework. M16 narrows Session Blueprint deferred details for one PoC and requires **no new DDR** unless implementation reveals an actual ownership or permission conflict; stop and review such a conflict before expanding scope.

Implementation sequence after this contract is reviewed: additive schema and small Session lifecycle/inspection functions; optional header parsing and atomic scoped audit reservation; focused synthetic tests and existing regression; real synthetic manual E2E; validation/status documentation; independent review; then a separately authorized commit/push. None of those implementation or validation steps has occurred in this contract-only work.
